## 五、🔴 接手前必须知道的坑（都是踩过的）

### 1. 本机现在**有** PHP 了

`/opt/homebrew/bin/php`（**不在 PATH，用全路径**），**8.5.9**，扩展齐全。

- **改完 PHP 必须 `php -l`**。此前只能手数括号
- **但 `PDO 占位符数 = execute 参数数` 仍要自己查**，`php -l` 验不出来，**这是本项目最常翻车的点**
- 🔴 **本地 8.5，生产 8.2。别用 8.3+ 语法**
- 🔴 **本地 `php -S`，生产 nginx + PHP-FPM**。路径 / 权限 / `open_basedir` / OPcache 差异本地测不出

### 2. 本地完整环境已经能跑（21 号单做的）

```bash
/opt/homebrew/bin/php -S 127.0.0.1:8000 -t backend   # 首访自动 seed 建库
cd frontend && npm run dev                            # 代理默认已指本地
```

**dev 下滑块自动跳过**，判据是 `import.meta.env.DEV` **且** API 指向 loopback，
**双条件、不来自任何用户可控输入**。生产包里跳过分支**根本不存在**（已 grep 验证）。

登录用 seed 出来的账号——**10 号单改成随机密码落盘**，读 `backend/data/initial-admin-password.txt`。

### 3. `frontend/dist` 进 git

**动了 `frontend/` 必须 `npm run build` 并提交 dist**，否则线上不生效。

**重建 dist 后必须做回归检查**（共用工作区时一次 build 可能把别人的半成品打进包）：
```bash
grep -c "q-sign" frontend/dist/assets/index-*.js                 # 04：应为 0
grep -c "previewQuoteOverwrite" frontend/dist/assets/index-*.js  # 05：应 >0
grep -c "请先选择收款主体" frontend/dist/assets/index-*.js         # 06：应 >0
```

### 4. 这个仓库是**公开的**（老板 08-09 已定，不再讨论）

`github.com/eatpeach/xingxuan`。**绝不往里写**：账号密码、API 密钥、内部排期、其它项目信息、客户数据。

`.gitignore` 已改成白名单式（20 号单）。**验 `.gitignore` 不能用 `git check-ignore`**——
它默认跳过已追踪文件，且 `-q` 退出码 0 只表示「匹配到某条规则」（可能是 `!` 取反）。
**权威验法是造真文件跑 `git add -A --dry-run`。**

### 5. 滑块不要绕

登录页有滑块人机验证。**两个开发都拒绝代过，CTO 背书了这个判断**：

> 有账号只说明**被授权访问**，不等于**被授权冒充人类通过验证**。

**需要线上验证时，请真人在浏览器里登录一次，把登录态留着。**

### 6. 级联删除是真的，而且不留痕

```
customer_quotes → orders → contracts / payments / commissions
```

已在隔离库实测：直接 `DELETE` 一条报价，订单/收款/返佣**一起 1→0**。

🔴 **方法论**：**孤儿数据为 0 不能证明"没发生过"**——FK 开着时级联删得干净，不留孤儿。
可证伪的判据是「`op_logs` 记过 `create_from_quote` 但 `orders` 查不到」。

### 7. 大量「后端做完了、前端没入口」的功能

`Quotes.tsx`（1409 行）**全仓零 import**，带走 8 个能力。同类情况还有
`quickCreateInvoice`、`markInvoicePaid`、`adoptSupplierQuote`、`uploadInquiryAttachment`、
`create/update/deleteSalesperson`、`markup-rules` 四个 action。

🔴 **接手时的通用动作**：看到「后端有 handler」**先 grep 前端有没有调用**，
再看那个调用点所在的文件**有没有被 import**。**两层都要查。**
