## 需求（老板 2026-08-10）

> 滑块设置下，如果在本地测试环境，不显示。

## 🔴 但不能只做这一半——只跳过滑块 = 把生产的门拆了

`frontend/vite.config.ts` 现在把 `/api` 和 `/storage` **代理到生产站 `https://www.xingxuan.cc`**。

所以「在 localhost 上跳过滑块」的实际效果是：**在本地脚本化登录生产后台**。
那正是这个控件要防的事——**等于把门拆了，还以为只是开了个测试通道。**

**必须两件一起做：**

1. **本地跑自己的后端**（本机已装 PHP 8.5.9，`php -S` + 本地 seed 出来的临时库）
2. **只有在"后端也是本地的"时候**才跳过滑块

这样才成立：**本地实例是自己的、库是假的、账号是 seed 出来的——滑块保护的东西一个都不在场。**

## 要做什么

### 1. 本地后端跑起来

```bash
/opt/homebrew/bin/php -S 127.0.0.1:8000 -t backend
```

首次访问任意 API 会 `initialize()` → 建表 + seed。**seed 创建用户名 `admin`，密码随机生成**
（10 号单已落地：不再是硬编码的 `admin123`）。**随机密码写在 `backend/data/initial-admin-password.txt`**
（已 gitignore），第一次触发 seed 后 `cat` 该文件拿密码登录。库已存在时不会重建、不会重写此文件。

> ⚠ **21↔10 耦合已处理（A，08-10）**：10 号单把 seed 密码从硬编码改成随机落盘。
> 本地登录方式随之从「admin/admin123」变为「admin + 读 `initial-admin-password.txt`」。
> `CLAUDE.md` 的本地启动说明已同步更新。

⚠ 本地库落在 `backend/data/xingxuan.db`，**和生产同名**。确认它被 gitignore
（20 号单已改成白名单，`data/*` 全忽略），别提交进去。

### 2. vite 代理改成**默认指本地，可显式切生产**

现在写死指生产。改成读环境变量，**默认本地**：

- 默认 → `http://127.0.0.1:8000`
- 显式指定（如 `VITE_API_TARGET=https://www.xingxuan.cc npm run dev`）→ 指生产

**默认值必须是本地。** 默认指生产的话，谁忘了设变量就在拿生产练手。

### 3. 滑块只在"确定是本地环境"时跳过

判据你定，但**必须同时满足两个条件才跳过**：

- 构建期是 dev（`import.meta.env.DEV` —— `vite build` 出来的产物这个值恒为 `false`）
- 运行期 API 指向本地

🔴 **不要只用 `hostname === 'localhost'`** —— 那个条件下代理照样可能指生产。

**跳过时界面上要有显眼提示**（比如登录框上方一条黄色 banner：
「本地开发环境 · 已跳过人机验证」），**让人一眼看出这不是生产**。

## 🔴 红线：这单最大的风险是把生产的滑块弄没了

- [ ] **`npm run build` 出来的产物里，滑块逻辑必须完整存在**
- [ ] **生产环境任何情况下都不能跳过**——包括有人在生产域名下塞查询参数、改 localStorage
- [ ] **跳过的判据不能来自任何用户可控的输入**（URL 参数、localStorage、cookie 一律不行）

### 自证（照 20 号单的教训：不能用一个永远会通过的检查）

**必须造真产物验，不能靠读代码推断：**

```bash
cd frontend && npm run build
# 生产包里滑块逻辑还在吗
grep -c "请先按住滑块完成验证" dist/assets/index-*.js     # 应 > 0
# 跳过分支有没有被打进生产包
grep -c "已跳过人机验证" dist/assets/index-*.js            # 期望 0（被 tree-shake 掉）
```

**两条都要贴实际输出。** 若第二条不为 0，说明跳过分支进了生产包，
**即使它运行时不触发也要说明清楚为什么安全**——最好是让它压根不进包。

## 结论（B，2026-08-10）

### 判据：两个条件都必须成立，且**写在调用点**

```ts
// Login.tsx
const localDev = import.meta.env.DEV && isLoopbackApiTarget(__API_TARGET__)
```

- `import.meta.env.DEV` —— Vite 构建期静态替换，`vite build` 产物恒为 `false`
- `__API_TARGET__` —— `vite.config.ts` 的 `define` 注入的代理目标，
  值来自开发者自己机器的环境变量/默认值，**不来自浏览器里任何用户可控输入**
- 判据逻辑单独放 `frontend/src/utils/devEnv.ts`，**它是一道安全边界，单独成文件是为了能被一眼读完**

**`vite.config.ts` 的代理默认值改成了 `http://127.0.0.1:8000`。**
要对着生产看数据得显式 `VITE_API_TARGET=https://www.xingxuan.cc npm run dev` ——
**那种情况下滑块照常出现**，因为判据要求 API 指向本地。

### 🔴 第一版自证【没通过】，这条必须记下来

第一版把两个条件都包进 `isLocalDevEnv()` 一个函数里。读代码看没问题，**实测生产包里跳过分支还在**：

```
已跳过人机验证    1 处  🔴 进包了
本地开发环境      1 处  🔴 进包了
lg2-devbanner   1 处  🔴 进包了
127.0.0.1:8000  1 处  🔴 进包了
```

**原因**：`import.meta.env.DEV` 在函数体内被替换成 `false` 之后，
esbuild **不做跨模块的常量传播** —— 调用点拿到的仍是一个「函数调用」而不是字面量 `false`，
于是 banner 的 JSX 和文案照样被打进产物（虽然运行时永远不可达）。

**改法**：把 `import.meta.env.DEV` 这道门**移到调用点**，
`false && ...` 折叠成 `false` → 整个分支被 DCE 删掉。改完复测：

| 检查 | 结果 |
|---|---|
| `请先按住滑块完成验证` | **2 处 ✅**（滑块逻辑完整存在） |
| `按住滑块拖动到最右` / `验证通过` / `lg2-slider` | 各 2 处 ✅ |
| `已跳过人机验证` | **0 处 ✅** |
| `本地开发环境` / `lg2-devbanner` | **0 处 ✅** |
| `isLoopbackApiTarget` / `LOOPBACK_HOSTS` / `__API_TARGET__` | **0 处 ✅** |
| `127.0.0.1` | **0 处 ✅** |

→ **不是「在包里但不触发」，是生产包里根本不存在这段代码。**

**这正是 20 号单那条教训的复现**：如果只读代码推断「DEV 在生产是 false 所以没事」，
就会漏掉这个——**必须造真产物 grep。**
